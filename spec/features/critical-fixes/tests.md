# Тесты

**Context:** Проверка критичных фиксов в детекции dead code: коллизии имён, alias import, CommonJS binding, ложные экспорты через return-object и публичный API.

## Functional tests

1. Коллизия символов между файлами
- Тип: automated
- Подготовка: два файла с одинаковым именем символа, где в одном файле символ используется, а в другом нет.
- Ожидание: в отчёт попадает только реально неиспользуемая декларация; использование одноимённого символа в другом файле не маскирует проблему.

2. ESM alias import (`import { a as b }`)
- Тип: automated
- Подготовка: модуль экспортирует `a`, импортёр использует только `b`.
- Ожидание: нет записи `a (imported but not used)`; импорт считается использованным.

3. CommonJS `const local = require('pkg')`
- Тип: automated
- Подготовка: импорт внешнего пакета и последующее использование `local`.
- Ожидание: импорт не попадает в dead code report.

4. CommonJS `const local = require('pkg').member`
- Тип: automated
- Подготовка: использование только `local`, без упоминания `member`.
- Ожидание: анализ usage ориентируется на `local`; ложного предупреждения по import нет.

5. `return { ... }` не трактуется как module export
- Тип: automated
- Подготовка: локальная функция возвращает объект с локальной переменной, которая больше нигде не используется.
- Ожидание: переменная не получает искусственный статус exported и корректно считается dead code.

6. Экспорт публичного API без internal import
- Тип: automated
- Подготовка: файл библиотеки экспортирует функцию, которая не импортируется в пределах сканируемой папки, но является публичным контрактом.
- Ожидание: в стандартном режиме не появляется ложный dead code для такого export.

## Non-functional tests

1. Производительность до/после
- Тип: automated/manual (скрипт + фиксированный набор файлов)
- Ожидание: время выполнения не ухудшилось более чем на 20% относительно базовой версии на одинаковом датасете.

2. Стабильность CI-режима
- Тип: automated
- Подготовка: запуск с `--ci` на чистом наборе и на наборе с реальной проблемой.
- Ожидание:
  - без dead code: exit code `0`;
  - при dead code: exit code `1`.

3. Совместимость CLI-флагов
- Тип: automated/smoke
- Ожидание: `--folder`, `--ignoreNames`, `--ignoreFolders`, `--quiet`, `--no-progress` продолжают работать без регрессий.

## Data and caching tests

Not required — reason: инструмент не использует внешние кэши или персистентные data store; состояние анализа in-memory в рамках одного запуска.

## Integration and fallback tests

1. Интеграция с mixed codebase (ESM + CJS + TS)
- Тип: automated
- Подготовка: набор файлов с комбинированными типами импортов/экспортов.
- Ожидание: единый отчёт без ложных конфликтов между форматами.

2. Fallback при недоступных/битых файлах
- Тип: automated
- Подготовка: в дереве есть недоступный файл (ошибка чтения).
- Ожидание: анализ не падает, завершает обработку доступных файлов и выдаёт корректный отчёт для них.
